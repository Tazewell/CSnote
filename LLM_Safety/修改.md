这篇综述要讲的不是“LLM 安全有哪些工作”，而是一个更硬的判断：**系统形态一旦从模型走向可执行工作流，安全问题会发生质变**。在模型阶段，风险主要体现为输出端的静态内容失范；系统进入 Agent 阶段后，模型的语言能力被接到工具、权限与状态，风险开始以动作执行的形式出现；当多个 Agent 形成协作结构后，风险不再是单点失效，而会沿着信息流、分工链与反馈回路传播，形成级联放大；最终在真实应用里，系统承受的是行业约束与不可逆后果，安全不再是“把输出管住”，而是“把整个工作流管住”。

因此，现有研究的核心问题不在于“方法不够多”，而在于**研究对象被切碎**：模型安全、Agent 安全、多智能体安全、应用安全各写各的，导致一个典型结果——**结构性断层**。模型层的对齐与过滤默认“输出即终点”，但真实系统里输出会被当作指令、参数与状态更新；运行时输入与工具返回引入了持续的上下文缺失；模型/代理/工具/权限的边界交叉，使防御边界变得模糊。于是你会看到：某个模型在基准上很安全，但一旦接入工具链、记忆与协作结构，系统仍然能被劫持、被诱导、被污染，甚至在没有明显“违规文本”的情况下做出高风险动作。

你的全文要用一个统一坐标系把这些现象串起来：**五维安全维度 + 攻击者能力 × 系统边界**。五维维度负责回答“风险是什么形态”（内容、交互、系统一致性、隐私、系统性风险）；能力×边界负责回答“风险通过什么权限与链路落地”。这个坐标系的目的不是重新分类文献，而是解释一个关键事实：**跨层失效才是主问题**，而不是任何单层的指标好不好看。

接下来，全文按“机制—系统—应用”的节奏推进：

**第3章（模型层）**先把底座讲清：对齐、拒答、过滤与安全神经元等机制确实能降低静态内容风险，但它们天然脆弱——能被去对齐、能被提示操控、能在多语言/多模态中失效；更重要的是，它们的防御对象仍是“输出文本”，并不能覆盖“输出被执行”这一类风险。

**第4章（智能体层）**提出第一次跃迁：Agent 把模型接到工具、记忆与闭环规划。此时“安全”不再主要是合规回答，而是是否会调用、触发、篡改、劫持工具链；是否会在长期记忆中固化污染；是否会在多步规划中产生越权与副作用。你用 Agent-SafetyBench、R-Judge 等证据告诉读者：即使模型层看似安全，闭环一旦形成，安全性会系统性下滑，这就是结构性断层的第一种表现。

**第5章（多智能体系统层）**提出第二次跃迁：MAS 里即便每个 Agent 都“局部安全”，系统仍可能整体失控。原因不是某个 Agent 突然变坏，而是交互耦合带来的涌现：同伴压力导致收敛、共识制造导致偏差放大、任务分工导致责任稀释、信息流导致提示感染与语义漂移。PsySafe、MAEBE、ESRH 等在这里承担“系统证据”的角色：它们证明风险是结构性的、传播性的，而不是单点的。

**第6章（应用层）**完成落地：在真实领域里，风险沿着“模型脆弱性 → 闭环执行 → 组织拓扑 → 行业后果”这条链条放大。你把“Agent vs MAS”的区分撤掉，改用“真实系统”作为主语，分别写软件安全、金融、医疗、具身、信息生态：每个领域都有硬约束与责任链条，因此安全的关键不在“模型更对齐”，而在“工作流闸门、权限边界、审计与复核”。这一章的作用是把前面抽象机制变成具体失败路径，让读者看到：跨层失效不是概念，而是会变成可执行订单、可写入病历、可修改代码、可触发物理动作、可操纵舆论的不可逆后果。

八章

第8章你可以把它写成“把前面所有章节的证据压成几条可检验的判断 + 一套研究议程”，而不是常见的“未来可以做什么”。顶会最看重的是：你能不能把综述写成**立场鲜明、能指导下一波研究**的东西。下面给你一个可直接落地的写法建议（不需要列表也能写，但我先用结构把“该写什么”讲清楚，你落笔时把它变成连续段落）。



## 8章应该扮演的角色：把“跨层失效”说成可操作的科学问题

你引言里提出的是：LLM→Agent→MAS→真实应用的演进，让安全从静态内容走向可执行、可传播、可放大的系统性风险；现有方法存在结构性断层。第8章的任务就是回答三件事：

1. **断层到底断在哪里**（不是一句“复杂了”，而是可定位的断点）
    
2. **哪些研究路径是“看起来在做安全、其实在修补错层”**（批判性）
    
3. **下一阶段应该怎么做才算“跨层安全”**（给出可验收标准，而不是口号）
    

写作上，你可以把第8章当作“论文的第二个引言”，但这次不是提出问题，而是提出**结论与判据**。



## 推荐的章节骨架（按顶会口味写）

### 8.1 回应引言：为什么“模型安全好”不等于“系统安全”

这一节不要重复前文，而是提炼一个强结论：  
**前面3–6章的共同证据说明，安全失败更像是链路问题而不是点问题。**  
你可以用三句话把链路钉死：

- 模型层提供的是“输出端合规”的保证，但真实系统的危险行为往往发生在“输出被解释为指令/参数/状态”之后。
    
- Agent 把模型接到工具、权限与记忆，安全问题的主战场变成运行时：输入、工具返回、状态更新、闭环计划。
    
- MAS 把失败模式从“单体不当行为”变成“交互耦合下的涌现与传播”，局部安全无法推出整体安全。
    

这里要强调你的立场：**跨层失效是第一性问题**，而“再做一个更强的过滤器/更严格的对齐”往往只是把问题留给下游系统爆炸。



### 8.2 批判性部分：当前研究最容易踩的三类“伪进展”

顶会喜欢这种“你说清楚什么是无效努力”的段落，但要讲得技术化、可验证，而不是情绪化。

**（A）把安全当作静态基准分数，忽视工作流后果**  
很多工作把“拒答率下降/ASR下降”当成胜利，但真实系统的关键不是“说不说”，而是“会不会做”。如果评测不包含工具调用、权限边界、状态更新和审计链条，那么提升的可能只是“文本端的表观安全”，而不是系统风险下降。  
你可以在这一段明确提出一个判据：**任何声称提升 Agent/MAS 安全的方法，都应该在可执行工作流中展示“危险动作率下降且任务可用性保持”。** 做不到，就只能算模型安全改良，而不是系统安全。

**（B）把防御理解为叠加模块，忽视边界与责任链**  
现实工程里最常见的失败是：模型对齐 + prompt guard + 输出过滤 + 事后审计，看上去很完整，但一旦工具权限配置、日志、回滚机制、人工复核策略没设计好，系统仍然是“可被诱导执行”的。  
你要明确批判：**模块堆叠并不自动收敛为端到端安全**，因为风险沿链路传播，防御也必须沿链路闭合——尤其是“动作执行前”的闸门与权限分级。

**（C）把 MAS 风险归结为“某个 agent 坏了”，忽视结构诱发**  
许多解释会把系统性失控讲成“某个代理被攻破/越狱”，但MAEBE/ESRH这类证据指向的是：拓扑、信息可见性、监督角色缺失、奖励与激励结构，本身就可能诱发集体偏移。  
你可以提出一个更强的结论：**在MAS里，安全属性属于系统结构，不属于某个组件。** 因此防御不能只做“更安全的个体”，还要做“更安全的交互结构”。



### 8.3 未来方向要写成“研究议程”，并且给出验收标准

这一节建议你用你前面提到的“三个张力”做主轴，但每个张力都要落到“可研究的问题 + 可评估的指标”。

**张力1：能力 vs 安全**  
未来不是“越安全越好”，而是要解决安全带来的能力损失、拒答、延迟和协作崩塌。你可以把研究问题写成：如何定义可接受的安全-效用前沿？如何在不同应用里设定不同的“安全预算”？  
验收标准可以是：在相同任务完成率下显著降低危险动作率，或者在相同危险动作率下提高任务完成率。

**张力2：自动化 vs 可控性**  
Agent/MAS的风险来自自治闭环，因此未来方向应当强调：把可控性做成系统属性，而不是靠人工盯。比如：

- 动作级权限与分级授权（什么能自动做、什么必须复核）
    
- 可回滚与可验证执行（失败可逆、过程可审计）
    
- 运行时监控与“升级人工”的触发条件（什么时候必须停）  
    验收标准：出现高风险信号时能稳定触发降级/停止，并且不会被简单提示绕过。
    

**张力3：开放性 vs 责任**  
真实系统最终受监管、合规、责任追溯约束。你可以提出一个尖锐观点：**没有责任链条的开放系统，其安全讨论是不完整的**。  
未来研究要把“谁对什么负责”纳入系统设计：日志、证据、解释、可追责接口。  
验收标准：事故发生时可以重建因果链（输入—决策—工具—状态—后果），并能定位责任边界，而不是只能说“模型幻觉了”。



### 8.4 你最能体现作者见解的一段：提出 2–3 条“强主张”

这一段建议你写得非常硬，像综述的贡献宣言，但带批判与可检验性。给你三个可直接用的“强主张模板”（你选两三个即可）：

- **主张1：系统安全的第一性指标不是“有害文本率”，而是“危险动作率及其可逆性”。**
    
- **主张2：任何跨层防御都必须把“工具与权限”当成威胁模型的一等公民；否则所谓 Agent 安全只是把风险延迟到执行端爆炸。**
    
- **主张3：多智能体安全研究如果不显式建模交互结构与治理角色，只优化个体代理的对齐，最终得到的可能是“更一致地犯错”的系统。**
    

顶会读者会喜欢你把立场说得这么明确——前提是你在前面章节确实用证据铺垫过（你现在的结构是足够的）。



## 写作层面的“顶会化”建议（非常关键）

- **少写“未来可探索”，多写“如果要算进展，必须满足X”**：把讨论章写成评审无法反驳的判据。
    
- **每节都要“回扣第1章问题”**：不断提醒读者你在回应“跨层失效”。
    
- **把“应用是放大器”写成机制，而不是比喻**：强调传播路径、责任链、权限边界、状态更新这些硬对象。
    
- **敢于指出当前主流路线的盲点**：但用“缺少什么证据/缺少什么设定/评测缺什么变量”的方式批判，别用情绪词。

七章
对第七章我会更“苛刻”一点：它应该是你这篇综述的**技术心脏**，甚至比第8章更像“作者贡献”。第8章负责立场与议程；第7章要把立场落成**可复用的框架、可解释的传播路径、可执行的防御组合原则**。你现在的结构很好，第7章的位置也刚好——它必须把第3–6章的证据压成一套统一理论。

下面是我对第7章最关键的意见（按顶会写法来）：

---

## 1) 第7章不要写成“防御方法大拼盘”，而要写成“跨层传播模型 + 协同防御的组合律”

顶会最不吃的一种第7章是：把模型层对齐、Agent guardrails、MAS 辩论、应用权限控制按层罗列一遍，然后说“需要结合”。这会被评审认为是“常识性结论”。

你要做的，是把它写成一个明确的主张：

- **风险不是按层产生、按层消失的**；它沿链路传播，并且在进入 **动作执行(Action Execution)** 后更容易从**单点触发**走向**级联放大(Cascading Amplification)**。
    
- “把防御叠起来”之所以不够，是因为存在**结构性断层(Structural Gap)**：运行时输入/工具返回造成**上下文缺失**，以及模型/代理/工具/权限之间的**防御边界模糊**。
    
- 因此协同防御必须针对“传播路径”设计，而不是针对“层级”堆料。
    

这三句话，建议在 7.1 开头就钉死。

---

## 2) 我建议第7章用一个“风险传播图”做总控：你需要一个统一对象

第7章最容易写散，因为你在跨四层讲事情。解决方式是：给全文一个统一的“对象模型”，比如**链路图/因果图/攻击图**：

- 节点：模型（生成/对齐状态）、代理组件（规划/记忆/工具）、系统结构（拓扑/监督/权限）、环境与人（输入源、外部系统、合规/责任链）
    
- 边：信息流（提示/检索/共享记忆）、控制流（工具调用/写入/执行）、激励与治理（监督、审计、协商）
    
- 你所有“风险放大”都用同一张图解释：从哪个边进来，在哪个节点被放大，最后在哪个执行边落地。
    

这样写的好处是：第6章每个领域都能“回扣同一张图”，第8章也能把未来方向绑定到图上的薄弱边。

---

## 3) 防御部分要写“防御原语（primitives）+ 组合原则（composition rules）”，而不是“防御手段”

我建议你把第7章防御体系拆成两层：

### 7.x 防御原语：每个原语解决哪一类传播边

原语不要太多，5–7个足够，而且要写得像工程与安全系统都认可的“硬件件”：

- **权限与最小特权**：把“能做什么”变成可证明的边界
    
- **执行前闸门**（例如 execute–refuse–verify、双人复核、不可跳过确认）：把高风险动作从文本层提前到动作层控制
    
- **沙箱与可回滚**：把不可逆性变成可逆性
    
- **可追溯日志与证据链**：把事后归因变成可还原因果链
    
- **记忆卫生**（写入准入、分区、过期/撤销、来源标注）：把“长期污染”变成“可隔离污染”
    
- **多智能体治理结构**（监督者角色、异质性、反共识机制）：抑制“集体自信地错”
    
- **输入与工具返回的溯源与隔离**：专门对付上下文缺失与提示注入的跨信道传播
    

### 7.x 组合原则：为什么不能简单叠加

这一小节必须写得尖锐，因为这是你“原创洞见”的核心。你可以明确写出两到三条组合律：

- **非单调性**：加一个过滤器可能让代理更依赖剩余信道，反而提高高风险动作概率（典型“边界模糊”副作用）。
    
- **替代通道**：封住文本输出不等于封住执行，因为系统里还有工具参数、记忆写入、检索结果、其他Agent消息这些“侧门”。
    
- **责任稀释**：多Agent分工如果没有审计链，会把错误从“可定位故障”变成“不可归因事故”。
    

这几条不是口号，而是你用第4–6章的案例“回扣”的规律：读者会感觉你在做系统理论，而不是做文献清单。

---

## 4) 第7章一定要给“可验收的评测协议”：否则框架会被评审认为不可落地

顶会评审经常会问：你这个框架怎么验证？  
所以第7章最好给一个简洁但硬的评测协议，强调“跨层安全”应该如何测：

- **把指标从输出端迁移到动作端**：不仅测ASR/拒答率，还要测危险动作率、越权调用率、不可逆后果率。
    
- **测传播与爆炸半径**：单点触发后能影响多少组件/多少轮/多少外部状态（这就是级联放大的量化）。
    
- **测恢复能力**：检测时延、回滚成功率、人工接管成功率。
    
- **测责任链完整性**：是否能重建输入—决策—工具—状态—后果的因果链。
    

这一段写出来，你的第7章就不像“愿景”，而像“研究范式”。

---

## 5) 结构建议：第7章最好长这样（逻辑顺序很关键）

如果你愿意改到最顶会的形态，我建议顺序是：

1. **7.1 跨层传播：从静态内容到动作执行的风险跃迁**（把术语放在这里集中打出，不要到处撒）
    
2. **7.2 传播路径与放大器**（记忆、工具、拓扑、治理、环境输入五类放大器）
    
3. **7.3 协同防御原语**（只讲原语与作用边，不讲“某篇论文怎么做”）
    
4. **7.4 组合原则：为什么不能简单叠加**（这是你的刀锋）
    
5. **7.5 跨层评测协议与指标**（让框架可检验）
    
6. **7.6 用第6章做两个“贯穿案例”回扣**（比如“金融交易链”“CVE修复链”各用半页，证明框架能解释真实失败）
    

这样写，评审读起来会很清楚：你不是在“总结”，你在“提出一套统一方法论”。

---

## 6) 我会建议你在第7章加一句更狠的“判据”

这句判据能显著提升顶会味道：

> **如果一个方法只能降低静态内容违规，却不能在动作执行链路上降低危险动作率或缩小级联放大半径，那么它最多是模型安全改进，而不是跨层系统安全。**

这句话是你第7章的“审稿人过滤器”：它让你整篇综述的评价标准更严格、更像研究贡献。
