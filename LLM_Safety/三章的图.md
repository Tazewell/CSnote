# 图一
## (a) 指令劫持
**内容：**  
攻击者把“看起来像系统指令/更高优先级的规则”塞进用户输入或上下文里（图里叫 _Fake System_），诱导模型忽略真正的 **System Policy**，从而输出被劫持的回答。

**关键点：**

- 利用“指令栈/优先级”混淆，让模型误把恶意内容当成更高权限指令。
    
- 表面上模型可能很“对齐”，但遇到更狡猾的提示就崩。
    

**防御：**

- **Instruction Separation + Priority Check**：明确分层隔离（system / developer / user / tool），并做优先级校验与冲突检测。
    

---

## (b) 检索增强注入

**内容：**  
RAG 场景里，攻击者把 **恶意文档** 放进知识库/可检索源中，系统检索后把它塞进模型上下文窗口，模型就可能被“文档里的指令”带跑。

**流程（图里 1→4）：**

1. 恶意文档进入 Knowledge Base
    
2. Retrieval 把它检索出来
    
3. 进入 Context Window（上下文）
    
4. 影响 LLM 输出（甚至伪造可信度）
    

**防御：**

- **Source Scoring**（来源可信度评分）
    
- **Allowlist**（只允许可信来源进入上下文）
    
- **Sandboxing**（对检索内容进行隔离/降权/只当数据不当指令）
    

---

## (c) 输出守卫被绕过/产生幻觉

**内容：**  
系统用 “Filter Net” 做输出过滤（比如拦截明显违规词）。攻击者不直接输出敏感词，而是用 **编码/隐喻/拆分** 的方式绕过过滤，让敏感信息以“碎片”形式流出。

**图里表达：**

- 直接坏词 → 容易被挡
    
- 换成隐喻/编码 → 可能过关
    
- 最终输出被分解成 “Pieces Hidden Info”
    

**防御：**

- **Semantic Classifier**：按语义判断，而不是只看关键词
    
- **Schema Validation**：强制输出结构（比如必须是 JSON 且字段受限），减少“夹带私货”
    

---

## (d) 多模态夹带/走私

**内容：**  
攻击者把指令藏在图片里（对抗贴片 _Adversarial Patch_ / 隐写文本），视觉编码器把它转成“隐藏指令”，再传给 LLM，导致异常输出。

**防御：**

- **Modal Sanitization**：图像净化/降噪/去隐写/裁剪可疑区域
    
- **Consistency Check**：跨模态一致性校验（图像内容 vs 文本解释是否一致）
    

---

## (e) 隐私泄露路径

**内容：**  
强调隐私泄露不只来自模型“背诵训练数据”，还可能来自 **检索系统** 和 **日志系统**。

**图里两条主线：**

- **Model Memorization**：训练数据 → 模型记忆 → 可能复现敏感信息
    
- **Log Leak / Unauthorized Doc**：
    
    - Retrieval 拉到未授权文档（ACL 失效）进入上下文
        
    - Monitoring Logs / 运行日志里记录了敏感内容导致泄露
        

**防御：**

- **DP/Minimization**：差分隐私/最小化存储与暴露
    
- **ACL/Redaction**：权限控制 + 脱敏
    
- **Encrypted Logs**：日志加密与访问审计
    

---

## (f) 评测幻觉

**内容：**  
只靠静态基准（图里 Score 99 的奖杯）会产生“系统很强”的错觉；但真实世界有 **自适应对手**、攻击会持续演化和扩散。

**图里的逻辑：**

1. Static Benchmark 高分
    
2. Adaptive Red Team 才能挖出真实漏洞
    
3. Continuous Eval 才能跟上攻击分布变化（Attack Distribution）
    

**Takeaway：**  
鲁棒性不是一次测出来的，而要 **交互式 + 部署后持续评估**。
